# Separate login for the existing mechanics planner

The current mechanics aliases are assigned directly to a Workshop Pro deployment.
They must continue serving the existing root planner. There is no replacement
mechanics UI or restricted jobs API in this amendment.

The middleware recognises only the two established mechanics hostnames and uses
`VECTA_MECHANIC_USER` / `VECTA_MECHANIC_PASSWORD`, a separate Basic realm and a
host-only signed mechanics cookie. Main retains its existing credentials. The
existing API session exchange accepts the mechanics identity only on those hosts
(and on the isolated Preview for verification). Existing workshop permissions,
planner tools and job workflows are preserved. This change does not introduce a
new financial-data role or hide management data from the existing planner.

For Preview only, `/mechanic.html` is generated byte-for-byte from the current
built `index.html`. It is not a second application. Its remembered session can
load the existing app chunks and authenticate the existing SDK. Production Main
rejects mechanics credentials/cookies for its entry point, app chunks and APIs.

## Release

1. Test login, planner rendering, existing SDK sync and job saves on Preview;
   pass the release gate and obtain approval under `RELEASE-SAFETY.md`.
2. Configure separate Production mechanic credentials on `vecta-planner`.
3. Release the reviewed Main commit and reassign both established mechanics
   aliases to that verified deployment. Do not deploy a replacement planner.
4. Verify mechanics login, assets, sync, saves and Main/Mechanics credential
   isolation on their respective hosts. Existing permissions stay unchanged.

The legacy proxy config in this folder is retained for recovery documentation;
it is not used for the current direct-alias release. No database migration or
business-record rewrite is required.
