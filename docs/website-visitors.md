# Website visitor counters

Requested by Chris on 5 November 2026: show today's website visitors to the right of Workshop Pro, above the day's takings, with yesterday alongside.

The manager header reads `/api/admin-website?visitors=1` once a minute while visible. Counts always refer to UK calendar dates, independently of the selected planner date. Unknown, untracked and unavailable figures display an em dash; a tracked day with no visits displays zero. The tooltip identifies the partial first day. Mechanics do not fetch or display these totals.

The public homepage, booking and tracking pages send a small, non-blocking visit request. A keyed daily hash of the Vercel-provided IP and browser user agent deduplicates repeat requests across pages and tabs. This is an estimate of unique visitors: matching browsers on one connection may merge; changing browsers or networks may count again. No cookies or tracking identifiers are added to browser storage. The optional “Ignore my visits” link saves only an opt-out preference on the public website in that browser; use it separately on each device/browser. It also removes the current browser/network’s earlier visit today. Clearing site storage clears this preference. Opening the public website with `?vecta_visitors=include` restores counting. Raw IPs, user agents, URLs, registrations and customer details are not stored. Known bots, automated browsers, Do Not Track and Global Privacy Control are excluded. Preview hosts do not collect visits and Test deployments cannot write live counts.

## Database and rollout

Apply `scripts/website-visitors.sql` to the isolated Test project before testing the hosted preview, then to Main before the approved release. Both tables and all three RPCs are private to the service role, with RLS enabled and no anonymous or authenticated grants. The existing environment helper prevents a Preview deployment from accessing Main. Collection records its start time on the first accepted visit; it cannot recover earlier days. The graph phase retains up to 90 UK calendar days of daily hashes, with older rows removed on the next accepted visit.

## Click-through graphs (phase 2)

Chris approved the counter release and requested graphs on 5 November 2026, accessed by clicking the counter. The heading and both daily values now form one accessible button. It opens a native dialog with seven-day and thirty-day grouped bars, total daily visitors, confirmed online bookings and booking rate. Exact daily figures and the definitions are available in an expandable section. No chart library or paid analytics service is added. History is requested only while the dialog is open, with date validation, bounded requests, retry/offline states, Escape/close and restored focus. Phone charts fit without horizontal scrolling. Mechanics never load the graph script. The existing dashboard baseline is unchanged.

Apply `scripts/website-visitor-graphs.sql` after the counter migration. It is additive and compatible with the previous collector during rollout; Test was migrated and transaction-verified on 5 November. The phase-2 migration has NOT been applied to Main. All history and booking-attribution tables/RPCs are service-role only. The new history endpoint requires the existing manager session. The SQL retains only actual recorded history (at most yesterday from the older two-day collector); missing days remain null. The first tracking day and today are marked partial.

The public collector sends only browse/progress classification or a signed booking receipt. A receipt is issued only after a booking request is saved, is bound to its UUID and UK creation date, expires 15 minutes after creation, and cannot be extended by retries. Tracking is optional and cannot turn a saved booking into a failure. The browser sends its receipt directly to the collector so proxy IP addresses cannot become visitor identities. The database verifies the actual request and deduplicates its UUID. No registration, customer details, full URLs, IPs or browser strings are saved in analytics.

Confirmed bookings are tracked website requests with `status=booked` and a linked job. Pending requests are shown separately; declined, deleted and archived requests are excluded. Counts are attributed to the request day, even when accepted later. The booking rate uses distinct daily browsing visitors with an accepted booking divided by all tracked daily browsing visitors. Progress-only visits do not enter this denominator; two bookings by one visitor count once in the numerator. Period totals sum daily uniques, not unique people across a week/month. Privacy exclusions or failed analytics delivery can make totals lower than the full booking inbox. Previous requests cannot be linked retrospectively and are not presented as tracked conversions.

The existing opt-out suppresses both visits and booking receipts on that browser. Removing today's visitor cascades to that day's analytics booking links without changing the real booking. It cannot erase earlier daily hashes after they have rotated; enable it on each browser before making future test bookings.
